# Защита клиентов и VPS: как пользоваться

## С чего начать

Откройте «Клиенты». Разрешённый доступ и текущий online — разные вещи. Клиент может быть включён, но не подключён. При недоступных метриках показано «Статус неизвестен», а не «Офлайн».

Для статистики включите «Endpoint → Сессии и трафик по клиентам». Endpoint кратко перезапустится. Listener метрик должен оставаться на `127.0.0.1`; наружу его открывать не нужно.

Список обновляется каждые 15 секунд, при скрытой вкладке опрос браузера приостанавливается. Фоновый сбор работает, пока запущена панель. «Последний онлайн» — время последней наблюдавшейся активной сессии, не точная дата выключения телефона. Короткие подключения между измерениями могут остаться незамеченными.

Трафик — загрузка и отдача из метрик endpoint, без привязки к тарификации провайдера. Первый образец включает доступный счётчик текущего запуска; более старая история неизвестна. При перезапуске endpoint учитывается новый запуск. Неполученный перед остановкой остаток трафика восстановить нельзя. После перезапуска панели база не сбрасывается. Это эксплуатационный учёт, не гарантированно точный биллинг.

## Ограничить передачу доступа

1. Создайте отдельную учётную запись для каждого устройства.
2. Откройте «Управлять → Антишаринг». Настройте квоту и/или срок. Время срока указывается в UTC; последнее наблюдение online отображается в часовом поясе браузера.
3. По умолчанию политика только наблюдает. Для автоотзыва отдельно включите его и подтвердите возможное переподключение остальных клиентов.
4. Квота — общий накопленный трафик этой записи, не месячный пакет. `0` или пустое поле снимает квоту. Квота проверяется по валидным метрикам; при сбое учёта она не отключает доступ. Проверка срока продолжается отдельно.
5. Лимиты соединений H2 и H3 задаются независимо. `1 + 1` допускает одну сессию каждого транспорта, а не гарантирует одно устройство. Слишком малый лимит может мешать переподключению или клиенту с несколькими upstream-соединениями.

Смена IP сама по себе не вызывает бан: телефон может перейти с Wi-Fi на мобильную сеть, а несколько людей могут находиться за NAT. Метрики endpoint показывают один агрегированный наблюдаемый IP, не список устройств. Последняя активная запись автоматически не отключается; требуется решение администратора.

## Одноразовое приглашение

В карточке клиента откройте «Одноразовая выдача профиля». Выберите срок, транспорт и тип ссылки. Нужна HTTPS-панель.

Отправьте приглашение лично получателю. После кнопки «Получить профиль» он увидит `tt://?` ссылку и QR. Повторное получение невозможно, поэтому профиль нужно импортировать до закрытия страницы. Просмотр страницы и предпросмотр мессенджера приглашение не расходуют.

В базе хранится SHA-256 случайного секрета, а не полный URL. Секрет передаётся во фрагменте `#`, не в GET-запросе или Referer. Новое приглашение отменяет старое. Есть отдельная кнопка отзыва. Пароль и циклы отключения/включения клиента также инвалидируют ранее выданные приглашения.

Уже полученный профиль остаётся копируемым. Для его отзыва отключите клиента или смените пароль, затем выдайте новый профиль. Не используйте один логин для разных людей.

## AntiDPI и TLS-аутентификация

В «Безопасность» доступны настройки штатного AntiDPI, ClientHello-профиля, DNS, ответы HTTP и подготовка TLS-auth ссылок. Изменение параметров по умолчанию не меняет текущие TOML. Для выбранного клиента есть отдельная кнопка обновления сетевых параметров с повторным импортом.

Разработчики закрыли [issue #80](https://github.com/TrustTunnel/TrustTunnelFlutterClient/issues/80) 22.10.2026 и подтвердили поддержку TLS-аутентификации в App v1.3. Это не означает, что старая версия приложения или endpoint 1.1.0 её поддерживает. Проверяйте фактически установленную версию; наличие App v1.3 в каждом магазине отдельно не подтверждено.

Порядок: подготовить новые ссылки, отдельно установить совместимый endpoint, проверить все устройства и только затем включить обязательный режим. Профиль с ключом не заменяет пароль или проверку сертификата. Ключ передаваем вместе с профилем, поэтому это не аппаратная привязка.

На проверенной паре endpoint `1.3.0-beta.2` / CLI `1.3.0-rc.2` HTTP/2 отвергает неверный и отсутствующий ключ с AntiDPI включённым и выключенным. QUIC этого испытания не прошёл. Панель не разрешает включить обязательный режим при QUIC; автоматического отключения QUIC и перехода на beta нет. Настоящий Android-клиент пользователя этим испытанием не заменяется.

HTTP-камуфляж скрывает часть характерных ответов, но не открытый порт, сертификат, IP или статистические свойства потока. Post-quantum усиливает алгоритм обмена ключами, а не скрывает VPN. Универсальный обход DPI не обещается.

## Безопасность VPS и маршруты

Запустите проверку в «Безопасность». Отчёт предлагает конкретные исправления: NTP, права файлов, SYN cookies, изоляцию метрик и ограниченный набор sysctl. Каждое применяется отдельно с подтверждением. Профиль ядра не трогает `rp_filter`, маршруты, MTU и UDP. Ошибка применения вызывает откат изменённых значений.

Панель не отключает SSH-пароль автоматически: сначала нужно проверить вход по ключу в отдельной сессии и доступ к консоли провайдера. Публичная HTTPS-панель остаётся административной точкой входа; наиболее закрытый режим — localhost с SSH-туннелем.

В «Маршрутизация» отмечен текущий выход. Выберите новый и подтвердите применение. Повторное применение того же режима не перезапускает VPN. Каскад требует адрес внешнего SOCKS5-прокси; для интерфейсного WARP он не нужен. Для игр сохраняйте уже проверенный интерфейсный режим. Проверка WARP не является измерением пинга игровой сессии.

Строгая TLS-защита блокирует переустановку, смену endpoint и сброс правил, пока администратор явно не отключит её. Восстановление строгой политики из backup проверяет совместимость назначения. Не запускайте одновременно несколько операций переустановки, сертификата и изменения защиты.
